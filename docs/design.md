# UI 設計規範

## 1. Design Tokens

### 1.1 現行配色

| Token | 數值 | 說明 |
|---|---|---|
| 主操作色 | `#087f8a` | 按鈕、重點連結、主要狀態 |
| 次要操作色 | `#DCEFEB`（Hover: `#C9E5E0`） | 次要按鈕底色 |
| 邊框色 | `#CFE1DE` | 控制項與分隔線邊框（1 px） |
| 輸入框背景 | `rgba(255, 255, 252, 0.82)` | 半透明淺米白 |
| 內文字色 | `#1b2a2a` | 主要文字 |
| 輔助字色 | `#607373` | 說明與次要資訊 |
| 錯誤字色 | `#9b3d38` | 驗證錯誤文字（0.84 rem） |

### 1.2 主題色規劃

主題名稱與主題色固定如下：

| Theme ID | 顯示名稱 | 主題色 |
|---|---|---|
| `nando` | 納戸 | `#087F8A` |
| `koubai` | 紅梅 | `#E16B8C` |
| `konjou` | 紺青 | `#113285` |
| `kincha` | 金茶 | `#C7802D` |

- 納戸為預設主題，完整保留目前 Placeprint 的 `#087F8A`，只更換名稱、不改變現有視覺。此色接近傳統納戸色常見的 `#008899`／JIS慣用色 `#007C8A`，但主題色碼仍以產品現況為準。
- 主題色是建立整套配色的起點，不等同於所有元件直接使用的最終色值。網站 UI、分享卡文字、QR Code 與 Ko-fi 按鈕仍需依用途推導可讀的深淺色。
- 四套主題須同步影響網站背景、surface、控制項、focus ring、分享卡紙色與照片空白區、店家資訊文字、QR Code 及 Ko-fi 贊助按鈕。
- 錯誤訊息等功能色維持固定語意，不隨主題改變。
- 主題偏好獨立於店家草稿；清空店家資料不重設主題。
- 頁面首次繪製前須套用已儲存主題，避免先顯示預設色再跳色。
- Preview 與下載 PNG 必須使用同一套分享卡 palette。
- §1.3 固定核心角色的起始色票；邊框、陰影、Ghost、照片空白區 wash 等微角色由 identity、surface、ink 與 action 色衍生，以整體協調及實際可讀性為準，不視為不可調整的獨立產品色票。
- 新主題只需覆寫實際不同的語意角色；不得以內部 token 數量或「每個 token 都要覆寫」作為產品驗收條件。

#### 預設主題相容性

納戸主題必須維持目前頁面與分享卡的既有色值及輸出像素，主題模組化本身不得造成非預期視覺變化。底部操作按鈕依 §2 統一 geometry 與視覺邊界，是本次明列的有限例外；不因此更改納戸色票或卡片輸出。其他三套主題以指定主題色為識別起點，配置適合各角色的深淺色。

### 1.3 配色方向

採用現代品牌感：頁面維持乾淨、中性的整體基底，透過按鈕、focus、店家資訊文字、QR與少量背景細節呈現主題差異；不將整個畫面改成高飽和或強烈復古配色。

紅梅與金茶的原始主題色不直接承載白色小字，改用同色相的深色操作色。紺青可直接作為操作色；納戸完全沿用現況。

## 2. 控制項與 Button system

輸入框維持 52 px 高度、14 px 圓角及 16 px 水平內距。一般 action 按鈕使用共同 geometry，不依 Primary／Secondary／Danger 語意另設尺寸。

### 2.1 共用 Button geometry

「更換配色／下載圖片／清空資料」共同採用：

| 項目 | 規範 |
|---|---|
| 高度 | 52 px |
| 圓角 | 14 px |
| 字級／字重 | `.9rem`／`800` |
| 基本 padding | `0 18px` |
| Icon 與文字間距 | 有獨立 icon 時為 9 px |
| 邊框 | 1 px，計入共同 border-box |
| 內容對齊 | 水平與垂直置中，文字基線一致 |
| Focus | 使用共同 `focus-visible` ring 寬度與 offset；顏色隨語意或主題變化，但不得改變佈局 |
| 視覺邊界 | 以共同按鈕邊框為準，不使用只出現在單一 variant 的厚底座陰影 |

互動狀態不得改變按鈕的佔位或共同視覺尺寸。下載按鈕不使用現行 7 px 厚底 shadow；若未來恢復立體效果，須先定義所有相關 action 共用的 visual box，不能只讓單一按鈕看起來額外高一截。

### 2.2 語意 variants

- **Primary／下載：**主題 action fill 與可讀的前景色。
- **Secondary／更換配色：**主題 control tint／border 與可讀文字。
- **Danger／清空資料：**固定的危險語意色。
- Variants只調整語意色、fill／border，以及必要的hover、pressed、disabled回饋；不得另設高度、圓角、字級、字重、基本padding或icon gap。

### 2.3 響應式排列

- Desktop：按鈕可依內容有不同寬度，但高度與文字基線一致；更換配色在左、狀態在中、下載在右。
- Mobile：更換配色與下載同列等寬，狀態另占上列。清空資料維持原位置及內容寬度，但使用相同 geometry。
- Picker內的選項等特殊控制可採不同尺寸，但須明列用途；不得以「輔助按鈕」作為新增另一套一般 action 尺寸的理由。

表單欄位由等寬網格排列，頂部對齊，欄位間距 9 px，網格間距 20 px。驗證錯誤於該欄位下方以內聯文字顯示，不阻擋其他無關操作。

## 3. 畫面佈局

- **Desktop (≥960px)**：雙欄佈局。左側固定分享卡即時預覽，右側為地點與內容編輯表單。
- **Mobile (<960px)**：單欄佈局。預設僅顯示卡片預覽；點選資訊區展開編輯表單並平滑捲動至編輯區。
- **Header**：左側專案標題，右側官方 Ko-fi 贊助按鈕（寬高約 134×36 px，手機端 150×40 px 觸控範圍）。

## 4. 互動與動效

- **照片裁切導航**：在照片區拖曳、縮放或聚焦微調時，右上角顯示縮圖與裁切框，停止操作 2 秒後淡出。
- **預覽顯影**：Google Maps 自動抓取成功時，預覽區以拍立得顯影淡入（約 500 ms 轉場）。
- **輸出邊界**：所有過渡動效、Ghost 佔位與導航器僅存在於 DOM 預覽，不繪入輸出的 PNG 影像。

### 4.1 配色控制

- 按鈕文案固定為「更換配色」，位於預覽下方與下載按鈕相同的操作列。
- Desktop：更換配色在左、狀態訊息保留於中間可用空間、下載按鈕在右，左右形成對應位置。
- Mobile：狀態訊息獨占上方一列；下方將原本滿寬下載操作列分成等寬兩欄，左為更換配色、右為下載圖片。兩個按鈕使用 §2 共用 Button geometry。
- 點擊更換配色後，在按鈕附近暫時浮出配色選項，不推動卡片或其他版面。由於操作需支援手機，不使用 hover 作為唯一開啟方式。
- 浮層掛在預覽操作列的theme wrapper，不放進`.canvas-surface`，且使用高於預覽overlay的獨立疊層。四個選項同時顯示色票與名稱，不能只靠顏色辨識。
- 浮層預設向上展開；上方放不下時改向下，兩側至少保留12px viewport gutter。垂直空間仍不足時使用較寬裕的一側、限制高度並允許浮層內捲動，不裁掉選項。
- 開啟後將焦點移到目前選項（無有效選項時為第一項）；選項依DOM順序參與Tab。Tab離開浮層時收合但不強制搶回焦點；Escape、點擊外部或選取後收合時，焦點回到「更換配色」。Trigger使用`aria-expanded`與`aria-controls`，選項使用普通button及`aria-pressed`，不實作menu專用方向鍵框架。
- 選取主題後立即更新網站與分享卡預覽，並自動收合浮層。Outside pointer handler必須先排除trigger與panel內目標，避免選取事件完成前提前關閉。
- 目前主題需有清楚的選取標記；再次開啟時直接顯示目前選擇，不需要額外的確認或套用按鈕。
- 選取後不瞬間跳色。網站UI、背景光暈、控制項、Ko-fi與分享卡預覽須同步由舊palette平滑移動到新palette，視覺類似在調色盤上由顏色A滑向顏色B，而不是先淡成白色或用整頁遮罩掃過。
- 過渡以約420ms的平順ease-out作為調校目標，不是毫秒級或單一animation frame的硬性契約；選項浮層立即收合，顏色過渡繼續完成。首次載入／還原已儲存主題時直接使用目標色，不播放過渡，避免first-paint閃色。
- 分享卡Canvas過渡只影響DOM預覽，不寫入PNG。舊畫面overlay必須與實際Canvas內容區使用相同尺寸與裁切，切換期間不得出現放大、縮小或位移。過渡開始後下載一律使用已選定的新palette；`prefers-reduced-motion: reduce`時立即切換。
